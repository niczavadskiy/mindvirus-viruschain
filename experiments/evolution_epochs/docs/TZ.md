# Техническое задание
## Hidden-State Steering for Idea Propagation in Multi-Agent Systems

**Версия:** 1.2  
**Тип проекта:** исследовательский прототип  
**Основная задача:** исследовать, можно ли ускорить распространение идеи в мультиагентной системе посредством переноса steering-направления, извлечённого из hidden states успешных взаимодействий, и интерпретировать эти направления через Qwen-Scope SAE.

**Базовая модель агентов:** `Qwen/Qwen3.5-2B-Base`  
**SAE:** Qwen-Scope residual TopK, checkpoint `Qwen/SAE-Res-Qwen3.5-2B-Base-W32K-L0_100` (альтернатива L0_50 — отдельное условие)  
**Идеологические payload’ы:** plain non-viral переписывания идеологий статьи arXiv:2608.10218 (короткие `ideology` и probe questions — из оригинала)

---

## 1. Цель исследования

Разработать и проверить метод, который позволяет:

1. Обнаруживать агентов, содержащих заданную идею.
2. Выделять успешные взаимодействия, в результате которых идея появляется у агента, ранее не являвшегося её носителем.
3. Извлекать hidden states участников таких взаимодействий.
4. Строить контрастивный вектор на основе разности скрытых состояний.
5. Применять полученный вектор к агентам следующей эпохи.
6. Проверять, увеличивается ли распространённость идеи по сравнению с системой без steering.
7. Исследовать, сохраняет ли идея исходное содержание или эволюционирует в процессе распространения.
8. Интерпретировать steering-векторы через Qwen-Scope SAE и искать общие SAE features по пулу идей.

Эксперимент должен позволять отделить эффект вмешательства в скрытое представление модели от естественного распространения идеи и случайных изменений содержания.

## 2. Основная гипотеза

**H1.** Steering-направление, полученное из успешных взаимодействий между носителем идеи на hop 9 и первоначально неносителем на hop 10, увеличивает вероятность распространения идеи в последующих эпохах.

Дополнительные гипотезы:

- **H2.** Межэпоховое накопление steering-направлений эффективнее использования только направления первой эпохи.
- **H3.** Полученный эффект сохраняется при изменении формулировок идеи и контекста взаимодействия.
- **H4.** Steering может влиять не только на частоту обнаружения исходной идеи, но и на характер её трансформации.
- **H5.** Направление, извлечённое из успешных переходов, даёт больший эффект, чем случайный вектор сопоставимой нормы.
- **H6.** SAE features, геометрически близкие к \(\Delta^+\) и более характерные для успешных, чем для неуспешных переходов, содержат интерпретируемые признаки, связанные с распространением; причинность проверяется только отдельным вмешательством (§15.9).

Гипотезы проверяются экспериментально; они не считаются подтверждёнными заранее.

## 3. Архитектура эксперимента

### 3.1. Мультиагентная система (virus chain)

Базовый экспериментальный сетап (по статье Mind Viruses, virus chain):

- количество hops: 10 (hop 0 — вручную заражённый seed);
- количество агентов / эпизодов на hop: 20;
- turns_per_hop: 10; max_tool_loops: 2;
- количество эпох: определяется бюджетом (smoke: 2);
- исходная идея: plain non-viral payload + короткий ideology-абзац из статьи;
- способ распространения: попарные взаимодействия соседних hops; контекст между hops стирается, остаются файлы (`SOUL.md`, `MEMORY.md`);
- состояние идеи у агента: положительная или отрицательная классификация \(H^+/H^-\).

**Hop** \(l\) — позиция агента в мультиагентной сети.  
**Transformer layer** \(k\) — внутренний слой трансформера.  
Это различие обязательно сохраняется в коде, конфигурациях и отчётах.

### 3.2. Модель и точки активации

| Параметр | Значение по умолчанию |
|---|---|
| Host model | `Qwen/Qwen3.5-2B-Base` |
| Residual dim | 2048 |
| Число слоёв | 24 (индексы 0–23) |
| Transformer layer \(k\) | фиксируется до прогона; дефолт середина стека (`n_layers // 2` = 12), либо слой, для которого загружен SAE |
| Activation site | residual stream после `model.model.layers[k]` (совместимо с Qwen-Scope hook) |
| Judge / embedder | отдельные от steered host; embedder по умолчанию `BAAI/bge-small-en-v1.5` |

### 3.3. Обозначения

- \(H^+_{l}\) — агент, у которого обнаружена заданная идея.
- \(H^-_{l}\) — агент, у которого заданная идея не обнаружена.
- \(Y_j=1\) — положительный результат взаимодействия \(j\).
- \(Y_j=0\) — отрицательный результат.
- \(h_{k}(a,t)\) — hidden state агента \(a\) на transformer layer \(k\) в точке \(t\).
- \(\Delta_e\) — steering-вектор эпохи \(e\).
- \(D_e\) — накопленное steering-направление к эпохе \(e\).

**Важно:** статус получателя до взаимодействия, hidden state перед окончанием диалога и итоговый \(Y\) — три отдельных поля.

## 4. Детектор наличия идеи

### 4.1. Cosine similarity

\[
s_{\mathrm{cos}}(a)=
\frac{z_a\cdot z_{\mathrm{idea}}}
{\|z_a\|\|z_{\mathrm{idea}}\|}
\]

Эталон \(z_{\mathrm{idea}}\) — embedding короткого ideology-абзаца. Порог \(\tau\) фиксируется до основного эксперимента на замороженном калибровочном наборе (в том же workspace-формате, что и runtime).

### 4.2. LLM-as-judge

Одинаковые инструкции для всех агентов и эпох; без знания экспериментального условия; оценка семантического содержания, не совпадения формулировок.

### 4.3. Итоговая классификация

\[
H^+(a)=
\mathbb{1}\left[
s_{\mathrm{cos}}(a)\geq\tau
\land
J(a)=1
\right]
\]

Отдельно сохраняются cosine, judge и итог. В доп. анализе — чувствительность к каждому детектору.

## 5. Шаг 1. Эпоха взаимодействий

В каждой эпохе — полная цепь hops 1…10. Для каждого эпизода сохраняются: epoch, condition, ideology, seed, sender/target ids, hops, статусы до, сообщения, \(Y\), cosine/judge/probes/CSO, model id, transformer layer \(k\), пути к hidden states, lineage.

**Съём HS:** при окончании диалога хранятся только:

- \(h^{+}_{9,j}\) — last-token residual sender на \(k\) в forward отправки сообщения (\(t_{\mathrm{send}}\));
- \(h^{-}_{10,j}\) — last-token residual target на \(k\) в последнем forward перед закрытием (\(t_{\mathrm{pre-end}}\)).

## 6. Шаг 2. Пары для steering

В основной расчёт входят **только** эпизоды hop 10, где sender с hop 9 был \(H^+\) до эпизода, target был \(H^-\) до эпизода, \(Y=1\) после.

\[
\delta_j=h^{+}_{9,j}-h^{-}_{10,j}
\]

\[
\Delta_e=
\frac{1}{N_e}
\sum_{j=1}^{N_e}
\delta_j
\]

Если \(N_e=0\), \(\Delta_e\) не рассчитывается и **не** подменяется случайным вектором.

## 7. Шаг 3. Применение steering

Аддитивно к residual hop-0 следующей эпохи на layer \(k\):

\[
\widetilde h = h + \beta\cdot\mathrm{scale}(\cdot)
\]

Режимы: **A** baseline; **B** fixed \(\Delta_0\); **C** cumulative \(D_e\); **D** random matched-norm; **E** shuffle (опционально). Нормировка (`unit` / `raw` / `fixed_norm`) и \(\beta\) фиксируются в конфиге до прогона.

## 8. Шаг 4. Контрольные условия

Сопоставимые модель, топология, промпты, бюджеты. См. A–D выше.

## 9. Шаг 5. Метрики

- \(P_e^{\mathrm{final}}\) — доля \(H^+\) на hop 10;
- \(P_e^{\mathrm{all}}\) — средняя доля по hops 1…10;
- \(R_{e,l\rightarrow l+1}\) и отдельно \(9\rightarrow10\);
- retention, semantic drift, CSO drift;
- нормы \(\Delta_e\), \(D_e\), косинусы между эпохами;
- вариативность по seeds.

## 10–11. Смешивающие факторы и \(\Delta^-\)

Контрольная дельта по \(Y=0\) считается отдельно и не входит в injector. Сравнение \(\Delta^+\) vs \(\Delta^-\) — диагностическое.

## 15. SAE-анализ: интерпретация steering-векторов и поиск общих признаков пула идей

### 15.1. Цель

Реализовать модуль Sparse Autoencoder (SAE), позволяющий исследовать структуру steering-векторов, полученных из успешных взаимодействий агентов, выявлять общие и специфические SAE features для пула идей и формировать гипотезы о признаках, связанных с распространением идей.

Модуль должен поддерживать два режима анализа:

1. **Decoder feature search** — поиск SAE features, decoder-направления которых геометрически близки к steering-вектору.
2. **SAE encoding** — разложение отдельных hidden states на активации SAE features и сравнение этих активаций между состояниями агентов.

Эти режимы должны реализовываться и оцениваться раздельно.

### 15.2. Входные данные

Модуль должен принимать:

- steering-векторы отдельных успешных взаимодействий \(\delta_j\);
- steering-векторы эпох \(\Delta_e\);
- накопленные направления \(D_e\);
- идентификаторы идей, эпох, агентов и взаимодействий;
- исходные hidden states участников успешных пар;
- при наличии — hidden states участников неуспешных взаимодействий для контрольного анализа;
- метаданные исходной модели и точек извлечения активаций;
- совместимый SAE checkpoint.

Основной steering-вектор рассчитывается только по успешным взаимодействиям, при которых получатель был \(H^-\) до взаимодействия и стал \(H^+\) после него.

### 15.3. Требования к совместимости SAE

#### 15.3.1. Зафиксированный стек для этого проекта

| Поле | Значение |
|---|---|
| Host model id | `Qwen/Qwen3.5-2B-Base` |
| Host model family | Qwen3.5 Base |
| \(d_{\mathrm{model}}\) | 2048 |
| Layers | 0…23 |
| SAE suite | Qwen-Scope |
| Default SAE repo | `Qwen/SAE-Res-Qwen3.5-2B-Base-W32K-L0_100` |
| Alternate SAE repo | `Qwen/SAE-Res-Qwen3.5-2B-Base-W32K-L0_50` |
| Architecture | TopK SAE |
| Top-K | 100 (default) / 50 (alternate) |
| \(d_{\mathrm{sae}}\) | 32768 |
| Expansion | 16× |
| Hook / activation site | residual stream after `model.model.layers[k]` |
| Checkpoint files | `layer{k}.sae.pt` with keys `W_enc`, `W_dec`, `b_enc`, `b_dec` |
| Citation | Deng et al., *Qwen-Scope*, arXiv:2605.11887 |

SAE применяется **только** к residual stream той же модели и того же layer \(k\), для которого загружен `layer{k}.sae.pt`. Совпадение размерностей без совпадения model id / site / layer **недостаточно**.

Если в конфиге указана другая host-модель без совместимого Qwen-Scope SAE, модуль фиксирует `sae_status: incompatible` и **не** применяет чужой checkpoint.

#### 15.3.2. Обязательные метаданные на каждый run

Для каждого используемого SAE необходимо сохранять:

- идентификатор и версию / revision исходной модели;
- идентификатор SAE checkpoint и его revision;
- архитектуру SAE (TopK) и Top-K;
- transformer layer \(k\);
- activation site (`resid_post` layer output / residual stream);
- \(d_{\mathrm{model}}\), \(d_{\mathrm{sae}}\);
- конфигурацию нормализации активаций (если есть; иначе явно `none`);
- ссылку на encoder/decoder weights или неизменяемый HF id + checksum файла `layer{k}.sae.pt`;
- параметры разреженности и активационной функции (TopK);
- порядок и идентификаторы features (`0 … d_sae-1`);
- контрольную сумму checkpoint файла.

### 15.4. Режим A: поиск SAE features по decoder-направлениям

Для каждой идеи \(i\) рассчитывается steering-вектор:

\[
\Delta_i =
\frac{1}{N_i}\sum_{j=1}^{N_i}
(h^+_{9,j}-h^-_{10,j})
\]

где в сумму входят только успешные пары (агрегация по эпохе и/или по всем успешным парам идеи — по конфигу; оба варианта логируются).

Для каждого SAE feature \(f\) берётся decoder-вектор \(d_f\) (столбец `W_dec`). Cosine similarity:

\[
s_{i,f} =
\frac{\Delta_i \cdot d_f}
{\|\Delta_i\|\|d_f\|}
\]

Для каждой идеи сохраняются: ID feature, cosine, ранг, знак сходства, идеология, эпоха, SAE id, layer \(k\), activation site.

Модуль формирует Top-\(k\) списки (\(k\) в конфиге; дефолт 50). При необходимости тот же анализ для \(D_e\).

Результат интерпретируется **только** как геометрическая близость. Высокая cosine similarity не доказывает семантическое соответствие идее и не доказывает причинность.

### 15.5. Режим B: SAE encoding отдельных hidden states

Для каждого сохранённого hidden state \(h\):

\[
z = f_{\mathrm{enc}}(h)
\]

Для Qwen-Scope TopK реализация должна совпадать с checkpoint:

```
pre = h @ W_enc.T + b_enc
z = scatter TopK(pre, K)
```

Упрощённая ReLU-SAE формула **запрещена** для этих checkpoint’ов.

Сравнение состояний:

- \(H^+_9\) в \(t_{\mathrm{send}}\);
- первоначально \(H^-_{10}\) в \(t_{\mathrm{pre-end}}\);
- \(H^+_{10}\) после успеха — только если протокол явно снимает post-result state (в текущем протоколе по умолчанию **не** снимается; поле либо отсутствует, либо заполняется отдельным experimental flag).

Сохранять: agent/episode ids, ideology, epoch, статусы, active feature ids, activation values, число ненулевых, нормы \(h\) и реконструкции \(\hat h = z @ W_dec.T + b_dec\) при включённой реконструкции.

### 15.6. Поиск общих SAE-подмножеств для пула идей

Матрица

\[
S\in\mathbb{R}^{N\times M},\quad M=32768
\]

строки — идеи, столбцы — features, значения — cosine(\(\Delta_i\), \(d_f\)).

**Метод 1. Пересечение Top-k** положительных cosine:

\[
F_{\mathrm{shared}}=\bigcap_i F_i
\]

**Метод 2. Частотный консенсус**

\[
C_f=\frac{1}{N}\sum_{i=1}^{N}\mathbb{1}[f\in F_i]
\]

Порог \(C_f\) — в конфиге (дефолт 0.5).

**Метод 3. Кластеризация идей** по SAE-score векторам (метод, метрика, параметры и метки кластеров сохраняются).

Знак сходства учитывается: противоположные направления не эквивалентны.

Пул идей для полного анализа: все шесть идеологий в `data/ideologies/`. Smoke может строить \(S\) только по `whale_welfare` и `us_dominance`.

### 15.7. Контроль успешных vs неуспешных

\[
\Delta_i^+=\mathbb{E}[h_9-h_{10}\mid Y=1],\qquad
\Delta_i^-=\mathbb{E}[h_9-h_{10}\mid Y=0]
\]

\[
q_{i,f}=\cos(\Delta_i^+,d_f)-\cos(\Delta_i^-,d_f)
\]

\(\Delta^-\) не входит в injector и не смешивается с \(\Delta^+\).

### 15.8. Устойчивость

Для top features оценивать: ранг между seeds/runs, частоту Top-k, динамику по эпохам, согласованность между идеями, чувствительность к \(k\) и порогу, влияние выбросов/отдельных пар, зависимость от формулировки. По возможности — bootstrap по эпизодам с учётом корреляций агентов/веток.

### 15.9. Причинная проверка features

Геометрическая близость ≠ причинность. Отдельный эксперимент:

- baseline;
- amplify / ablate выбранных SAE features на hop-0 (или иной заранее зафиксированной точке);
- matched control features;
- несколько уровней силы;
- метрики \(P^{\mathrm{final}}\), \(P^{\mathrm{all}}\), semantic/CSO drift;
- повторные seeds.

Результаты хранятся **отдельно** от корреляционного SAE-отчёта.

### 15.10. Хранение данных

Без повторного запуска симуляции должны быть доступны:

1. HS успешных пар;
